Command line and Python¶

canVODpy runs from Python or from the command line. Both run the same code: canvodpy run creates a Site and processes the days with Site.pipeline(), so the stores hold the same data either way. Use Python to script runs, for example in a notebook, or in a loop over sites; use the command line for scheduled runs.

This page lists the options of both. For a first run, start with Retrieve VOD.

Process a period¶

from canvodpy import Site

site = Site("ExampleSite")
with site.pipeline() as pipeline:
    for unit in pipeline.run("2025001", "2025007"):
        print(sorted(unit.days), unit.vod.written)

canvodpy run --site ExampleSite --start 2025001 --end 2025007

Dates are YYYYDDD: the year and the day of year, for example 2025032 for February 1, 2025.

Command line Python Meaning
--site ExampleSite Site("ExampleSite") Site name under sites: in canvod-settings.yaml. One site per run; see Several sites.
--start, --end run(start, end) First and last day, both included; see Which days a run processes.
--update-to-latest run(update_to_latest=True) Instead of --start and --end: the days from the last stored day up to the latest day with files; see Update to the latest files.
--no-vod run(start, end, vod_analyses=()) Write the observations to the GNSS store and compute no VOD.
--vod-calculator run(start, end, calculator=...) The VOD calculator, tau_omega by default.
--dry-run pipeline.preview(start, end) or pipeline.preview(update_to_latest=True) List the days, receivers and files a run would process, without processing them.
--write-catalog write_catalog(stores_root_dir) after the run After a successful run, write the STAC catalog of every store under the data root. Without it, a run writes no catalog.
--label site.pipeline(label=...) Free-text label stored with the run in the run history, for example to group the repetitions of a benchmark.
--workers site.pipeline(n_workers=...) Number of worker processes.
--config-dir, -c CANVOD_CONFIG_DIR Folder that holds canvod-settings.yaml and recipes/, or the link of a settings file in a GitHub repository; see Where canVODpy finds the settings.
--config CANVOD_CONFIG_FILE Overlay file applied on top of canvod-settings.yaml.
--ephemeris-source processing.params.ephemeris_source in the settings final (orbit and clock products of an analysis center) or broadcast (the satellite angles an SBF file holds); see Ephemeris sources.
--vod-calculator VodComputer(site, calculator=...) VOD calculator; tau_omega unless a plugin adds others.
--dashboard None; run canvodpy dashboard Start the performance dashboard for the run's logs. --dashboard-host and --dashboard-port set its address. It stays up after the run until its button shuts it down; --dashboard-stop-at-end stops it with the run.

Options you leave out take their values from the settings file. In Python, set CANVOD_CONFIG_DIR and CANVOD_CONFIG_FILE before you create the Site:

import os

os.environ["CANVOD_CONFIG_DIR"] = "/path/to/config"

canvodpy run --help lists every option.

canvodpy run exits with code 0 when every receiver-day is written or skipped, or when --update-to-latest finds nothing new, and with 1 when it stops, for example on an error in the options or the settings. When it finishes but a receiver-day failed, it names the failed receiver-days and exits with 3; What the run does when something fails lists the reasons. A receiver-day that is written though some of its files failed counts as written. In Python, pipeline.failed_receiver_days lists the failed receiver-days.

Which days a run processes¶

A run processes the days you give it. There is no default: a run without --start or --update-to-latest stops with an error, and so does a run with --update-to-latest and --start or --end.

  • --start and --end give the first and last day. Without --end, the run ends today; in Python, run(start) without end ends on the last day with files. The run processes every day in the range. With the default gnss_store_strategy: skip, files that are already in the store are skipped, so running a day twice doesn't duplicate data, and a file that arrived late for a stored day is added.
  • --update-to-latest processes the days from the last stored day on; see below.

In Python, run(start, end) and run(update_to_latest=True) work the same way and raise a ValueError for the same mistakes. process_date processes one day, process_range the days from start to end.

Update to the latest files¶

canvodpy run --site ExampleSite --update-to-latest

The run chooses the dates and then runs as a run with --start and --end does:

  • Start: the earliest last stored day in the site's GNSS store, counting only the receivers with new files: files after their own last stored day, or files on that day that the store's log book doesn't hold. So a day stored while its files were still arriving, for example by a run at 03:00, gets the rest of its files on the next run; the files already stored are skipped. A receiver whose last day is completely stored and that sends no more files, for example one that was retired, doesn't hold the start back. A receiver with nothing stored yet counts from its first day with files.
  • End: the latest day on which a receiver has files.

It prints the dates it chose, for example update: 2026293 to 2026298. If no receiver has new files, it says so and exits with code 0. If the site's GNSS store holds nothing yet, it stops and asks for --start: the first run of a site names its first day.

A receiver whose files arrive a few days after the others sets the start, so its days are processed when they arrive. A file that arrives late for a day before a receiver's last stored day is not in the range; process that day again with --start and --end.

In Python, pipeline.update_range() returns the dates run(update_to_latest=True) would process, or None if nothing is new.

Several sites¶

A run processes one site. For several sites, run canvodpy run once per site, for example in a shell loop:

for site in ExampleSite OtherSite; do
    canvodpy run --site "$site" --update-to-latest
done

In Python, create one Site per site and run its pipeline.

The Site object¶

Site("ExampleSite") reads the settings of one site.

Attribute What it gives you
site.receivers All receivers of the site, from the settings
site.active_receivers The receivers a run processes: those not set to active: false
site.vod_analyses The receiver pairs under vod_analyses
site.gnss_store The GNSS store: observations and satellite angles
site.vod_store The VOD store
site.gnss_store_path, site.vod_store_path Where the stores are, from the settings; read-only
site.vod Computes VOD; see Compute VOD
site.pipeline() Creates a Pipeline for this site

Both stores are Icechunk repositories; see Storage.

A run creates a site's stores when it first writes data. Before that, site.gnss_store and site.vod_store raise a FileNotFoundError; the paths tell you where a run puts them.

The Pipeline object¶

A Pipeline reads the files, adds the satellite angles, and writes the GNSS store. Use it in a with block, which closes it at the end.

Method What it does
run(start, end=None, update_to_latest=False, vod_analyses=None, calculator="tau_omega") What canvodpy run does: stores the days from start to end (or, with update_to_latest=True, the days of Update to the latest files) in units of days, then computes the VOD of each unit's days from the GNSS store. Yields one RunUnit per unit: days (each day stored, with the groups that stored it), vod (the days with VOD written, already stored, or missing and why, per analysis) and vod_error (why the VOD of the unit failed, if it did). vod_analyses=() computes no VOD.
process_date(date) Processes one day and reads it back from the GNSS store. Returns one dataset per receiver.
process_range(start, end) Processes the days from start to end and reads each one back. Yields (date, datasets) for one day at a time. Use it to work with the data in Python; run reads nothing back and is faster.
preview(start=None, end=None, update_to_latest=False) Returns the days, receivers and files a run would process. Without dates, it covers every day it finds data for.
update_range() The first and last day a run with update_to_latest=True processes, or None if no receiver has new files.
failed_receiver_days The receiver-days of this pipeline that failed, as (receiver, date) pairs. Empty when every one is written or skipped.
close() Ends the pipeline. The with block calls it for you. The worker processes stay for reuse; see Parallel processing.

The datasets are xarray Datasets, keyed by store group: canopy_01 for a canopy receiver, and reference_01_canopy_01 for the data of a reference receiver paired with that canopy receiver.

The arguments of site.pipeline() override the matching settings under processing.params for this pipeline. Setting n_workers turns off the automatic choice of resource_mode: auto:

Argument Meaning
n_workers Number of worker processes
threads_per_worker Threads that numerical libraries use in each worker
keep_vars Observation variables to keep, such as ["SNR"]

The workers' CPU cores and priority come from the settings file; Parallel processing explains them.

Compute VOD¶

pipeline.run() computes the VOD of the days it stores. site.vod computes VOD for the receiver pairs under vod_analyses on its own.

From the datasets of one day, without writing:

with site.pipeline() as pipeline:
    for date, data in pipeline.process_range("2025001", "2025007"):
        vod = site.vod.compute_day_all(data, write=False)  # every pair
        # or one pair:
        # vod = site.vod.compute_day(data, "canopy_01_vs_reference_01", write=False)

Writing VOD this way (write=True, write_day) is deprecated; see Upgrading.

From observations already in the GNSS store, for example after you change the VOD settings, computed and written in the worker pool:

from datetime import date, timedelta

report = site.vod.compute_days(
    [date(2025, 1, 1) + timedelta(days=i) for i in range(31)],
    ["canopy_01_vs_reference_01"],
)
report.missing  # the days without VOD, and why

Each day of each pair is one task in the worker pool, which reads only that day from the GNSS store, so a day takes as long in a large store as in a small one. Without the list of analyses, every pair is computed. A day whose VOD the store already holds from the same GNSS files is not computed again (report.stored), so running it twice adds nothing. A day without data in the canopy or the reference group gets no VOD and is listed in report.missing.

To get the VOD of a time range back as one dataset, use site.vod.compute_bulk:

from datetime import datetime

vod = site.vod.compute_bulk(
    "canopy_01_vs_reference_01",
    start=datetime(2025, 1, 1),
    end=datetime(2025, 1, 31, 23, 59, 59),
)

It runs site.vod.compute_days for the days of the range, then reads the VOD from start to end back from the VOD store. start and end are times, both included: datetime(2025, 1, 31) alone would end at midnight at the start of January 31. With write=False, it reads the range into memory and computes the VOD there, without the worker pool, and writes nothing. site.vod.compute_bulk_all computes every pair.

canvodpy vod --site ExampleSite --analysis canopy_01_vs_reference_01 \
    --start 2025001 --end 2025031

The command runs site.vod.compute_days for whole days, from --start to --end; without them, for every day of the GNSS store. It lists the days without VOD.

A day can end up in the GNSS store but not in the VOD store, for example when writing the VOD failed. canvodpy run warns about such days. To list them and compute their VOD:

canvodpy vod-reconcile --site ExampleSite --analysis canopy_01_vs_reference_01
canvodpy vod-reconcile --site ExampleSite --analysis canopy_01_vs_reference_01 --execute

The VOD package page describes the VOD model and its output.

What only the command line does¶

canvodpy run adds a few steps around Site.pipeline():

  • It ends on today when you leave out --end; see Which days a run processes.
  • Before processing, it stops if a VOD store group holds VOD computed from data with other preprocessing settings. In Python, site.vod makes the same check when it writes.
  • It warns about days that are in the GNSS store but not in the VOD store.
  • If the VOD of a unit of days fails, it says which days are left without VOD and continues. pipeline.run() does the same and reports the error in RunUnit.vod_error.
  • It shows the progress per receiver.

Scheduled runs¶

To process new data every day, schedule canvodpy run with --update-to-latest, for example with cron at 03:00:

0 3 * * * /path/to/canvodpy run --site ExampleSite --update-to-latest --config-dir /path/to/config

For several sites, add one line per site, or call a script with the loop of Several sites.

Cron runs with a minimal environment, so give the full path to canvodpy (which canvodpy prints it) and to the settings folder. A scheduler can check the exit code: 3 means some receiver-days failed.

For Apache Airflow, check_day and process_day in canvodpy.workflows.tasks run the code of canvodpy run for one site and day. process_day raises an error when a receiver-day failed, so Airflow retries the task. Ready-made Airflow DAGs are an optional extension; see Optional extensions.
