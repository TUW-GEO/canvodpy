canvodpy API reference¶

Umbrella package of canVODpy: one supported surface, and the command-line tool on top of it. See API levels.

Site and pipeline (recommended)¶

Stateful orchestrator with factory integration and structured logging. What the command-line tool builds internally.

User-friendly wrapper around GnssResearchSite.

Provides a clean, modern API for site management while using the proven GnssResearchSite implementation internally.

Parameters:

Name Type Description Default
name str

Site name from configuration (e.g., "ExampleSite")

 required

Attributes:

Name Type Description

Site name
receivers dict

All configured receivers
active_receivers dict

Only active receivers
vod_analyses dict

Configured VOD analysis pairs
gnss_store MyIcechunkStore

Access to RINEX data store
vod_store MyIcechunkStore

Access to VOD results store

Examples:

>>> site = Site("ExampleSite")
>>> print(site.receivers)
{'canopy_01': {...}, 'reference_01': {...}}

>>> # Create pipeline
>>> pipeline = site.pipeline()

>>> # Access stores
>>> site.gnss_store.list_groups()

failed_receiver_days property ¶

Receiver-days of this run that failed.

(receiver, YYYYDOY) pairs, empty while every receiver-day is written or skipped. canvodpy run exits with code 3 when a run has any; the log says why each one failed.

close() ¶

End the run and release orchestrator resources.

loky's reusable executor is shared and left running.

run(start=None, end=None, *, update_to_latest=False, vod_analyses=None, calculator='tau_omega') ¶

Store the days from start to end, then compute their VOD.

The run of canvodpy run (ADR 0021). The GNSS phase stores the days in units of days and reads nothing back; after each unit, the VOD phase computes the VOD of its days in the same worker pool, from the GNSS store, and commits once (VodComputer.compute_days). Meanwhile, the GNSS phase works on the next unit. A day that failed gets no VOD and stays open for the next run.

Parameters:

Name Type Description Default
start str

First and last day (YYYYDOY). start is needed unless update_to_latest; without end the run goes to the last day with files.

 None
end str

First and last day (YYYYDOY). start is needed unless update_to_latest; without end the run goes to the last day with files.

 None
update_to_latest bool

Process the days from the last stored day on instead of start/end (:meth:update_range); with nothing new, the run yields nothing.

 False
vod_analyses sequence of str

The VOD analyses to compute; all the site's by default. An empty sequence computes no VOD.

 None
calculator str

The registered VOD calculator.

 "tau_omega"

Yields:

Type Description
RunUnit

Per unit, once its VOD is committed: the days stored and what the VOD phase did. A failing VOD phase is logged and reported in RunUnit.vod_error; the run goes on.

Raises:

Type Description
ValueError

If neither start nor update_to_latest is given, or update_to_latest comes with start or end.
NothingStoredError

With update_to_latest, if nothing is stored for the site yet.

Examples:

>>> with Site("ExampleSite").pipeline() as pipeline:
...     for unit in pipeline.run("2025001", "2025007"):
...         print(sorted(unit.days), unit.vod.written)

update_range() ¶

The days a run with update_to_latest processes.

It starts on the earliest last stored day in the site's GNSS store, counting only the receivers with new files: after their own last stored day, or on it but not in the store's log book. A day stored while its files were still arriving thus gets the rest, and a retired receiver doesn't hold the start back. It ends on the latest day with files.

Returns:

Type Description
tuple[str, str] | None

The first and last day (YYYYDOY); None if no receiver has new files.

Raises:

Type Description
NothingStoredError

If nothing is stored for the site yet.

Examples:

>>> with Site("ExampleSite").pipeline(dry_run=True) as pipeline:
...     pipeline.update_range()
('2026293', '2026298')

Factories¶

Bases: ComponentFactory

Factory for GNSS data readers.

All registered readers must inherit from GNSSDataReader ABC.

Supports two creation modes:

  • By name: ReaderFactory.create("rinex3", fpath=path)
  • By file: ReaderFactory.create_from_file(path) — detects RINEX v2, RINEX v3 and NMEA from the file's content (not SBF).

Examples:

>>> from canvodpy import ReaderFactory
>>> reader = ReaderFactory.create("rinex3", fpath="station.25o")

>>> reader = ReaderFactory.create_from_file("station.25o")

create_from_file(fpath, **kwargs) classmethod ¶

Auto-detect the file format and create the appropriate reader.

Detects NMEA (a .nmea extension or a first line starting with $), and otherwise RINEX v2 or v3 from the version in the first header line; a RINEX v3 file with signal-strength observables only gets the stripped RINEX v3 reader. SBF files are not detected: create their reader by name.

Parameters:

Name Type Description Default
fpath str or Path

Path to the GNSS data file.

 required
**kwargs Any

Additional parameters forwarded to the reader constructor.

 {}

Returns:

Type Description

Instantiated reader for the detected format.

Type Description

ValueError

If the format cannot be determined or no reader is registered for the detected format.

detect_reader(fpath) classmethod ¶

Name of the registered reader for the file at fpath.

Decided as in :meth:create_from_file: NMEA by its .nmea extension or its sentences, RINEX by the version in the first header line.
