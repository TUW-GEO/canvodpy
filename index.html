¶

An Open Python Ecosystem for GNSS-Transmissometry Canopy VOD Retrievals

canVODpy aims to be the central community-driven software suite for deriving canopy Vegetation Optical Depth (VOD) from the signal-to-noise ratio of the same GNSS signal, received at the same time by one receiver below the canopy and one with an unobstructed view of the sky.

Retrieve VOD from your GNSS data Contribute to canVODpy See canVODpy at work in molab

What makes canVODpy different¶

  •   One output for every file format

    Reads RINEX v2.11, RINEX v3.04, stripped RINEX v3.05, NMEA v4.00 and Septentrio SBF. Every reader returns the same validated xarray Dataset, so the rest of canVODpy never depends on the file format.

    Reading GNSS files

  •   Versioned storage

    Observations and VOD go into Icechunk stores. Every write is a commit that you can list, branch from and tag, like in git.

    Storage

  •   No duplicates, no overlaps

    Before it writes, canVODpy skips each file that's already in the store, by its SHA-256 hash. A file whose time span overlaps data of another file already stored stops the run, naming both files.

    Storage

  •   Hemispheric grids

    Seven grids divide the sky seen from the receiver into cells, among them equal-area, equal-angle, HEALPix, and geodesic grids. Each observation goes to the cell that contains it.

    Hemispheric grids

  •   Parallel by default

    canVODpy reads and processes files in parallel worker processes, and sizes the workers to the machine, or to the limits you set.

    Parallel processing

  •   Traceable

    Each release has a DOI. Each store records where its data came from, in metadata that follows DataCite and ACDD, and a STAC catalog describes all stores.

    Store metadata

Processing pipeline¶

flowchart LR
    FILES["RINEX, SBF or NMEA files"] --> READ["Read"]
    SETTINGS["Settings<br/>local folder or GitHub link"] --> READ
    OVERLAY["Overlay file<br/>optional"] -.-> SETTINGS
    RECIPE["Naming recipe<br/>optional, local file or GitHub link"] -.-> READ
    READ --> ANGLES["Satellite angles"]
    ORBITS["SP3 orbits"] --> ANGLES
    ANGLES --> GSTORE["GNSS store"]
    GSTORE --> VOD["VOD retrieval"]
    VOD --> VSTORE["VOD store"]
    VSTORE --> PLOT["Hemispheric grids and plots"]

Dashed arrows are optional inputs: an overlay file changes settings for one run (Configuration), and a naming recipe recognizes files with other names (Naming).

For SBF files, the satellite angles can also come from the files themselves (processing.params.ephemeris_source: broadcast). For every step of a run, see What a run does.

Packages¶

  •   canvod-readers

    Readers for the GNSS file formats, one output structure.

  •   canvod-auxiliary

    Downloads SP3 orbits and CLK clocks and interpolates them to the epochs of the observations.

  •   canvod-grids

    Hemispheric grids and the assignment of observations to their cells.

  •   canvod-vod

    VOD from the zeroth-order tau-omega model, and the base class for other VOD calculators.

  •   canvod-store

    The Icechunk stores for observations and VOD.

  •   canvod-viz

    2D polar plots and interactive 3D Plotly plots of the hemisphere.

  •   canvod-config

    Reads and validates canvod-settings.yaml.

  •   canvod-utils

    Date utilities, diagnostics, and tools the other packages share.

  •   canvod-preflight

    The canVOD file name convention: parses and builds canonical names, finds files whose time spans overlap.

  •   canvod-ops

    Preprocessing steps applied before VOD, such as temporal aggregation.

  •   canvod-store-metadata

    Writes, validates and exports the provenance metadata of a store.

  •   canvodpy

    The command line interface, Site.pipeline(), and the factories for readers, grids, and VOD calculators.
